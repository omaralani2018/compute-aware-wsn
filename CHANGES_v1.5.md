# Version 1.5

Version 1.5 accompanies the revised manuscript. It adds the analyses of Section 6.9 (robustness of the
Intel results) and Section 6.10 (confirmatory evaluation on Grand St Bernard), the training comparison
under `tm/`, a map from every table and figure, and from the main numbers quoted in the text, to the command and output that produce them
(`TABLES_AND_FIGURES.md`), and the record of when each protocol was frozen (`stb/FREEZE_RECORD.md`).
`SHA256SUMS_v1.5` lists every file added or changed.

## Added

- `src/`: `intel_variants.py`, `intel_variant_short100.py`, `segeval.py`, `test_segeval.py`,
  `intel_sens_run.py`, `v0_cells.py`, `intel_sens_report.py`, `intel_mote_blocks.py`, `radio_replay.py`,
  `effect_intervals.py` (Section 6.9; `effect_intervals.py` also Section 6.10).
- `results/`: `sens_{obs,short,short100}_{cheap,lightweight,cnn_lstm}.json` (every seed),
  `intel_variants_coverage.json`, `intel_sensitivity.json`, `v0_check.json`, `intel_mote_blocks.json`,
  `radio_replay.json`, `effect_intervals.json`.
- `weights_sens/`: the 120 models retrained on the three preparations of Section 6.9.
- `stb/`: `STB_frozen_2026-10-09.zip`, exactly as sent to the co-author, and the files of Amendment 1 in
  `amendment_1/` (see below);
  `FREEZE_RECORD.md`; `run_outputs/` with `stb_meta.json`, `stb_obs_cheap.json`, `stb_fill_cheap.json`,
  `runs/` (one result file and one attempt count per run), `weights_stb/`, `stb_summary.json`, `RUN_LOG.txt`
  and the two driver logs.
- `inputs/sensorscope/stbernard-meteo.zip`: the SensorScope file the protocol names (CC BY 4.0).
- `tm/`: the training comparison (see below).
- `TABLES_AND_FIGURES.md`, `CHANGES_v1.5.md`, `SHA256SUMS_v1.5`, and `SHA256SUMS_all` (the hashes of every other file of
  the package and of the cells archive).

The per-reading records (`cells/`) of Sections 6.9 and 6.10 (about 250 MB) are released as a separate
archive next to this package, `compute-aware-wsn-v1.5-cells.zip`, with its SHA-256 in `SHA256SUMS_v1.5`.
They let `intel_sens_report.py`, `intel_mote_blocks.py`, `radio_replay.py` and `stb_stats.py` be re-run
without retraining; the published-matrix records (`cells/v0_*`) are also regenerated by `v0_cells.py`, which needs the raw Intel
archive.

  stored.

  changed.
- `effect_intervals.py`: the phrase " (reviewer point 3)" removed from the end of the first docstring line, and
  the default path of the Grand St Bernard summary is now `stb_summary.json` in the run directory (it was

  `stb/amendment_1/synthetic_check_amended.log`: the absolute path of the directory they ran in is replaced
  by `<run directory>`; nothing else changed. The last of these is the one file of the Amendment 1 archive
  that differs from the archive as sent (`stb/FREEZE_RECORD.md`).
- The Grand St Bernard run used the frozen `stb_prepare.py`. Amendment 1 corrects its parsing order; the
  corrected file is in `stb/amendment_1/`, and both versions give byte-identical prepared data.

## Run steps

Section 6.9, inside `run/` (with `raw/data.txt`; copy `weights_sens/` to `run/` only to keep the shipped
models, since `intel_sens_run.py` skips seeds whose results are present):

```bash
mkdir -p cells
python3 test_segeval.py                               # evaluator check
python3 intel_variants.py                             # -> intel_segments_{obs,short}.pkl, intel_variants_coverage.json
python3 intel_variant_short100.py                     # -> intel_segments_short100.pkl, adds short100 to the coverage file
for v in obs short short100; do                       # remove sens_<v>_*.json from run/ first to retrain
  python3 intel_sens_run.py $v cheap
  python3 intel_sens_run.py $v lightweight 0 20
  python3 intel_sens_run.py $v cnn_lstm 0 20
done                                                  # -> sens_*.json, cells/<v>_*, weights_sens/
python3 v0_cells.py                                   # -> cells/v0_*, v0_check.json (published matrix, saved weights)
python3 intel_sens_report.py                          # -> intel_sensitivity.json (Table 10)
python3 intel_mote_blocks.py                          # -> intel_mote_blocks.json
python3 radio_replay.py                               # -> radio_replay.json
cp ../stb/run_outputs/stb_summary.json .
python3 effect_intervals.py stb_summary.json          # -> effect_intervals.json
```

To recompute the outputs without retraining, extract the cells archive into `run/` (it holds `cells/`) and
run the five lines from `python3 intel_sens_report.py` to `python3 effect_intervals.py stb_summary.json`
(the archive holds the `cells/v0_*` records, so `v0_cells.py`, which needs the raw Intel archive, is not needed).

Section 6.10, in a separate directory (the commands of section 7 of the protocol):

```bash
mkdir stbrun && cd stbrun
unzip ../stb/STB_frozen_2026-10-09.zip
cp ../stb/amendment_1/* .                             # the amendment and the corrected stb_prepare.py
cp ../inputs/sensorscope/stbernard-meteo.zip .
echo "2a78ee47f6bc8bab893d1db99ea33aad6b12682a50ee6796379d524464d5f9de  stbernard-meteo.zip" | sha256sum -c
sha256sum -c AMENDMENT_1.sha256                       # synthetic_check_amended.log is reported as changed (path)
sha256sum -c STB_FROZEN.sha256                        # reports stb_prepare.py as changed (Amendment 1)
python3 test_segeval.py && python3 stb_synthetic_check.py
python3 stb_prepare.py stbernard-meteo.zip            # -> stb_meta.json, stb_segments_{obs,fill}.pkl
bash stb_driver.sh A & bash stb_driver.sh B; wait     # -> stb_*_cheap.json, runs/, cells/, weights_stb/
python3 stb_stats.py                                  # -> stb_summary.json (Table 11)
```

To recompute `stb_summary.json` without retraining, copy `runs/`, `stb_obs_cheap.json` and
`stb_fill_cheap.json` from `stb/run_outputs/` and the `cells/stb_*` records from the cells archive into
`stbrun/`, then run `python3 stb_prepare.py stbernard-meteo.zip` and `python3 stb_stats.py`.

## Training comparison (`tm/`)

The experiment of `tm/TM_PROTOCOL.md` (version 3, frozen on 9 October 2026 by the message recorded in
`stb/FREEZE_RECORD.md`; the archive sent is `tm/TM_frozen_2026-10-09.zip`): the lightweight model, after its
main-study training of 200 epochs, is trained for 200 further epochs either on actual history (B+) or on
its own closed-loop reconstruction of the training span (C), from the same saved state, on eleven streams
with seeds 0 to 9. `tm/` holds the protocol, `TM_FROZEN.sha256`, the code as frozen, the run scripts, the
logs, one result file and one attempt count per (stream, seed) in `tm_runs/`, `tm_summary.json` (written by
`tm_stats.py`) and `TM_RESULTS.md` (a per-stream table of its values, with the run record). Section 7.1
of the paper summarises the outcome.

Check made for this version: `tm_stats.py`, run in a directory set up as in the run steps below with a copy
of `tm/tm_runs/` in it, rebuilds `tm_summary.json` byte for byte.

Run steps (in a directory set up as in section 7 of the protocol: the files listed in `TM_FROZEN.sha256`,
with the ten NAB files at the paths `nab_data.py` reads):

```bash
sha256sum -c TM_FROZEN.sha256
PYTHONDONTWRITEBYTECODE=1 python3 tm_synthetic_check.py      # generated data only
bash tm_driver.sh intel_time taxi traffic cpu machine_temp &
bash tm_driver.sh grok_asg_anomaly rds_cpu_util iio_networkin twitter_aapl exchange_cpc occupancy; wait
python3 tm_stats.py                                          # -> tm_summary.json
```
